# コスト30の同額対戦とキャラ別学習

2026-10-12、LearningLab 0.6.0。コストは設計者が決め、学習はHP・攻撃力・防御力だけを変更します。新しい`budget-wave`モードを使います。

## 設計者が決める値

正本は`configs/strength_assignments.json`の`assignments`と`costs`です。全42キャラの強弱と整数コスト1〜20を保存します。Unityの`Tools > LearningLab > 強弱設定`で変更できます。ゲームだけをcloneした場合はLearningLab側のJSONを選びます。JSONの編集はゲームアセットへ自動反映しません。

今回の初期割り当ては、ユーザーの委任に基づき、系統・役割・技・耐久・展開速度を踏まえて個別に設定しました。旧コストの一律変換ではありません。低コスト16体、中コスト21体、高コスト5体です。クロコダイルはユーザー指定で中コストの12にしています。[全42体の初期割り当てと理由](COST_DESIGN.md)。42体のゲームアセットの出撃コストにも、この初期割り当てを反映しています。HP・攻撃力・防御力の学習結果はゲームへ反映しません。

低コスト1〜5、中8〜12、高15〜20。ゲームのエナジー上限は30、初期値5、回復は1秒ごとに1です。Balance Editorのゲーム用コスト入力も1〜20に制限します。

## 対戦の条件

各軍の合計コストを正確に30へ揃えます。対象キャラを複数使うfocused編成と、対象を必ず含むmixed編成を評価します。余りを他のキャラで埋め、実際の編成と消費コストを記録します。固有キャラのパーティ枠は12、出撃人数は別であり、コスト1の30体も評価できます。観測容量を超える場合や正確な予算を使い切れない場合はエラーにします。

相手は味方設計の固定スナップショットを使います。相手の抽選表は対象キャラ・候補値・地形から独立し、同じseedと編成種別なら同じ相手と比較します。能力監査済み30種類がプールで、未対応12種類を対応済みとして扱いません。今回数値を学習するのはクロコダイルを含む9種類です。

地形は一直線と1マス階段の2枚、時間上限は90秒。両陣営を一度だけ出撃登録し、出撃口から順に登場します。追加出撃や敵AIの出撃判断はありません。

同じ編成を味方側・相手側へ入れ替えた2戦を行います。逆側の戦闘では候補定義も相手側へ移し、参照定義は固定します。こうして配置・陣営の挙動による有利不利を平均します。同じ固定編成同士の分析成績は0.5になります。

この評価は編成予算でコストを反映します。時間0の比較ではエナジー残高による出撃待ちを入れません。ゲームで高コストの出撃まで待つ時間や、途中で出撃を選ぶ価値を直接学習する実験ではありません。

## 強弱の目標と損失

主評価の対戦成績`match_score`は0〜1です。対象側が勝てば1、負ければ0。90秒で終了した場合は`0.5 + 0.25 × 拠点HP残率差 + 0.25 × 生存コスト比率差`です。逆側の対戦も対象キャラの側から見た成績に直します。

総与ダメージの2〜4などの絶対帯を主目標にする方式から、同額対戦の成績へ変更しています。初期目標帯はweak=0.40〜0.55、standard=0.45〜0.60、strong=0.50〜0.65、conditional=0.35〜0.65です。低コストでも同額なら使い道を持つ目標にしています。これらは設計の初期仮説で、バランス調整済みの保証ではありません。個体の絶対性能の順位や、conditionalの特定シナジーをこの1指標だけで保証するものでもありません。

目標帯からの逸脱を帯幅で割った値の二乗がcase損失です。キャラごとにcase損失を平均し、初期値からの変更罰則を加えます。探索範囲は従来の防御planを使います。今回の25項目は9体のHP・8体の攻撃力・8体の防御力です。アンモナイトの攻撃力、クロコダイルの防御力は設計値に固定します。コスト・技・速度・射程・攻撃周期も固定します。

## キャラ別の分布更新と採否

各キャラに独立した候補生成分布・Adam・乱数器を持たせます。候補1件の全train対戦が終わるたびに、該当キャラの損失だけでそのキャラの分布を1回更新します。あるキャラの改善・悪化は、他キャラの更新勾配へ入りません。最初の基準値評価は分布を更新しません。クロコダイルの中コスト化に合わせて探索対象へ加え、今回の対象は9種類です。24候補なら各キャラ23回、9キャラで計207回の更新です。

各キャラの評価済み候補から最良値を選び、組み合わせた候補をvalidationで測定します。未評価の分布中心を採用しません。validation全体の損失は悪化不可、キャラ平均は初期許容差0.01、case単位は0.05とし、全キャラ同時適用でも同じ条件を確認します。許容差は`validation_gate`で明示した初期設定であり、実測ノイズから算出した値ではありません。採用条件を緩めるだけで旧runの候補を採用する処理はありません。

採否後のholdoutは1回だけで、分布の更新や選び直しには使いません。ゲームへの自動適用はありません。チェックポイントはキャラ別の分布・Adam・乱数器を保存します。CLIのプロセス終了後の途中再開は引き続き未実装です。

9キャラ×2編成種別×2地形×4seed×2陣営で1候補288試合。24候補のtrainは6,912試合、その後にvalidation・必要な同時適用検証・holdoutを行います。

## WebUIで見られる図

- コストと同額編成の成績の散布図。役割を色で区別し、勝率・参考幅・試合数も表示します。
- キャラ中心編成同士の相性表。個体同士の1対1ではなく、合計コスト30の編成比較です。
- ペア編成の上積み。ペアを必ず含む同額編成の成績から、同じ相手・地形・seedでの単独中心編成2つのうち良い方の成績を引きます。余りを埋める相方も含む「編成の優位」で、純粋な因果的シナジーではありません。
- 試験した候補編成への採用率。同じ相手・地形・seedで最良の試験編成を選び、同点は等分します。実際に含まれた相方も計上します。プレイヤー使用率・PPO使用率・ランダム登場率とは区別します。
- キャラ別の基準・直近・最良スコアと更新回数、各数値の分布推移。

分析用seedはtrain/validation/holdoutから分離し、分析結果を分布更新・候補採否へ渡しません。開始時はキャラ中心編成の比較を先に測定し、学習・採否後にペアと採用率を測定します。未測定・予算超過は空欄です。試験したキャラと編成の範囲内での結果であり、全ての組合せの最適解ではありません。

勝率の参考幅はWilson式の95%区間です。鏡像対戦やseedの共有による相関を補正していないため、独立試合を仮定した参考幅として表示します。少数試合で強弱を確定せず、編成とseedを増やして確認します。

## 起動

単独リポジトリのルートでホストをビルド後、LearningLabディレクトリで実行します。

```powershell
python -m learning_lab.campaign --plan configs/cost_training_plan.json --template configs/cost_training_stages.json --output runs/cost-campaign
python -m learning_lab.dashboard --config runs/cost-campaign/experiment.json --settings runs/cost-campaign/targets.json --run runs/cost-search --port 8766
```

コスト・強弱を保存した後は新しいcampaignを作ります。旧runの入力や成績は上書きしません。保存物は従来のreport・trial・checkpoint・framesに加え、`roster-analysis-baseline.json`、採用候補がある場合は`roster-analysis-recommended.json`です。各分析JSONには実際の編成・合計コスト・各陣営の成績を残します。
