# 学習中の戦闘とパラメータをWebUIで確認する

0.6.0の同額対戦では、コスト・強さの散布図、相性表、ペア編成の上積み、試験編成への採用率、キャラ別の更新を追加しています。[新評価と起動手順](COST_BALANCE.md)。編成比較を測定している間は「編成を測定中」と表示し、学習前にキャラ中心の比較、学習後にペアと採用率を測ります。

2026-10-12、LearningLab 0.5.0。キャラ数値の候補生成分布を学習しながら、ローカルブラウザで実際の戦闘状態と更新の記録を確認できます。操作AIのPPO学習を表示する機能ではありません。

## 起動

単独リポジトリのルートでBattleHostを準備し、LearningLabディレクトリで新しいcampaignとrunを作ります。

```powershell
python scripts/prepare.py --build-only
cd LearningLab
python -m learning_lab.campaign --plan configs/defense_training_plan.json --template configs/defense_training_stages.json --output runs/defense-monitored
python -m learning_lab.dashboard --config runs/defense-monitored/experiment.json --settings runs/defense-monitored/targets.json --run runs/defense-monitored-search
```

[http://127.0.0.1:8765](http://127.0.0.1:8765)を開きます。ポートを変える場合は`--port`を指定します。サーバーはこのPCのループバックだけで待ち受けます。WebUIは学習開始と同じプロセスで動き、ブラウザを閉じても処理は続きます。学習が完了してもサーバーは残り、保存済みの対戦を見返せます。

## 見られる内容

| 表示 | 内容 |
| --- | --- |
| 戦闘フレーム | 実際のホスト状態から地形・拠点HP・キャラ座標・HP・攻撃中・出撃待ち・状態付与を俯瞰表示 |
| 保存した対戦 | 候補番号、対象キャラ、人数パターン、地形、split、seed、終了結果で区別 |
| 時刻スライダー | 保存したフレームを選んで、その時点の戦闘状態を確認 |
| 評価グラフ | 候補ごとのtrain探索スコアと、それまでの最良値。小さいほどよい |
| パラメータ表 | 設計基準、今回の評価値、生成中心の更新前後、中央80%の生成範囲、許可する上下限 |
| パラメータ推移 | 項目を選び、実際に試した値と更新後の分布中心・生成範囲を比較 |
| 候補の記録 | train損失、変更量罰則を含むscore、更新数、advantage、勾配norm |

Unityの描画フレームを撮影する方式ではなく、独立戦闘ホストの実座標とHPから2D表示を作ります。3Dモデルや攻撃エフェクトを再現した画像ではありません。原点・地形の位置、キャラの移動・戦闘・出撃待ちを確認するための表示です。倒れてホストの一覧から除かれた個体は、以降のフレームには表示されません。

初期状態と終了状態を必ず保存し、途中は通常10判断ごとです。判断間隔0.5秒の現行設定では戦闘時間5秒ごとの記録です。`--capture-every 2`なら1秒間隔にできます。保存とホスト状態取得の負荷は増えます。ブラウザの更新間隔と戦闘時間は別です。時刻スライダーは保存した状態を選ぶもので、未保存の途中フレームを補間するものではありません。

「最新に追従」を外すと、過去の対戦を選択して同じフレームに留まれます。時刻スライダーを動かしても追従は外れます。「以前の対戦」で過去の記録を100件ずつ読み込みます。個体のIDとHPはフレーム内の一覧にも表示します。

## 正しく進んでいるかを見る

最初の候補は設計基準値です。この全train評価が終わるまでは、完了候補数も更新回数も0です。基準値を評価してreferenceを初期化した後、次の候補を試し、1候補の全train試合が終わるたびに分布を1回更新します。24候補なら基準1件＋候補23件、更新は23回です。

防御planの通常設定は8対象×4人数パターン×2地形×4seedで1候補256試合です。24候補のtrainは6,144試合、その後にvalidationとholdoutを行います。表示の「今回の評価値」は、検証段階ではそこで比較している数値へ切り替わります。評価済み候補の推移グラフはtrainの履歴を表示します。

生成中心の変化や勾配normは、学習処理が実行されたかを確かめる手掛かりです。各回のスコア改善や最適化の完了を保証する表示ではありません。整数丸めで生成中心や候補値が同じになる場合もあります。初期防御0の分布中心が10（壁役20）になるのは、探索を始めるための初期化で、基準候補の防御値は0です。

戦闘中は、評価対象が出ているか、人数と編成が一致するか、直線・1マス階段を移動しているか、HPが減っているか、拠点戦や90秒上限で終了するかを確認できます。同じcase・seedでは候補間で編成を固定します。検証用・最終確認用の対戦で更新回数が増えることはありません。

## 一時停止・再開・停止

- **一時停止**: 判断境界で待機します。進行中の対戦、乱数器、分布、Adam状態はメモリに保持します。「一時停止中」の表示後は戦闘時刻が進みません。
- **再開**: 同じ対戦の続きから再開します。ブラウザが別のフレームを表示していても、学習自体の状態は変えません。
- **停止**: ワーカーを終了し、完了した候補・checkpoint・途中の保存フレームを残します。停止要求後の未完了候補を採用判定に使いません。WebUIは履歴表示のため残ります。

**プロセスを終了した後の中断再開は未実装です。** 「再開」は起動中のプロセスを一時停止した場合に使います。再起動には新しいrunディレクトリを指定してください。停止ボタンは確認を表示します。学習の終了・エラー・停止後には再開できません。

サーバーを終了するには、ターミナルで起動した場合はCtrl+Cを使います。別プロセスで起動した場合は、先にWebUIで学習を停止してからサーバープロセスを終了します。ブラウザを閉じるだけでは学習もサーバーも終了しません。

## 保存物と確認結果

| ファイル | 内容 |
| --- | --- |
| monitor.json | 最新の進捗、候補、分布、試行履歴、状態、エラー |
| episodes.jsonl | 完了した対戦のID、編成、地形、seed、結果、指標 |
| frames/episode-*.json | 1対戦の地形・候補値・実際の保存フレーム |
| trial-*.json / checkpoint.pt / report.json | 既存の探索記録・状態・最終検証結果 |

runはGitの対象から外します。短い検証記録は[monitoring_20261012.json](results/monitoring_20261012.json)へ保存します。表示を有効にしても候補・スコア・分布更新・最終判定が変わらないことを実戦テストで確認しています。WebUIの俯瞰表示、時刻選択、23項目の表示、一時停止時の時刻停止・再開をブラウザで確認しました。Windowsの一時的なファイル置換拒否には短い待機と再試行を入れ、拒否が続く場合はエラーを表示します。

2026-10-12の開始確認は進行中の実験の記録です。全24候補の完了結果や採用済みパラメータを意味しません。最終採否は既存のvalidation・全キャラ同時適用・holdoutの手順に従い、ゲームへの自動適用はありません。
